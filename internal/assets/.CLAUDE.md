# Asset Engine — Context for AI

## Purpose
Converts user-uploaded PNG files into terminal-renderable output using chafa.

## Asset Types
- spinner — animated PNG frames (frame1.png, frame2.png, etc.)
- icon — small inline graphics per icon key
- banner — wide header graphic on startup
- divider — horizontal separator line
- floater — corner decorative graphic
- mascot — reactive character with a trigger-driven state machine (see Mascot Triggers below)
- status-bar — bottom info bar with left/center/right zones and segments
- sound — WAV-based reactive sound effects, sharing the same trigger vocabulary as mascots

(The four types above were previously marked TODO in this file; they shipped in commit
d469f5f and have since had a security audit, sound-theme integration, and a bug-fix pass —
see /KNOWN_ISSUES.md and /VERIFIED_BASELINE.md at the repo root for current, verified status

## Render Modes (best to worst quality)
1. sixel — actual pixels, Windows Terminal + iTerm2 + Kitty
2. braille — ⣾⣽⣻ smooth, any terminal
3. blocks — █▓▒░ bold, any terminal
4. ascii — characters only, maximum compatibility

## Chafa Command Pattern
chafa --symbols [braille|block|ascii] --colors [full|256|16|none] --size WxH [image]

## Mascot Triggers

Each mascot state lists one or more triggers (`always`, `exit_code`, `command`,
`output_regex`, `env_var`, `git_status`, `idle_time`), each with an optional integer
`Priority` (JSON key `priority`, **nested inside the trigger object itself**, not as a
sibling of `triggers` at the state level — a manifest that puts `"priority"` next to
`"triggers"` instead of inside each trigger silently leaves every trigger at the
zero-value default). `ResolveState` (`internal/assets/mascot.go`) evaluates every state's
triggers against the current context and keeps the highest-`Priority` match
(`trigger.Priority > best.priority`, strict greater-than).

**Tie-break semantics: when two or more matching triggers share the same priority
(including the common case of both left at the default of 0), which one wins is
unspecified — resolution depends on Go's randomized map iteration order over
`MascotConfig.States` and can differ between separate process invocations for the exact
same input.** This was confirmed experimentally: with two triggers both effectively at
priority 0, the same `mascot-state --exit-code 42` invocation alternated between two
different results across repeated runs; once given genuinely distinct priorities, 8/8
repeated runs were deterministic. This is not a resolver bug — the priority-ordering logic
itself is correct — it is an authoring hazard: **any mascot with more than one trigger that
can plausibly match at once (most commonly an `always` idle state alongside anything else)
must give the non-default state(s) an explicit, higher `priority` than the default state,
or its behavior across shell sessions will be non-deterministic.** `cmdx asset validate`
does not currently warn about equal/default priorities on competing triggers — authors
should set them explicitly rather than relying on validation to catch the omission.

## Critical Rules
- ALWAYS check ChafaAvailable() before rendering
- ALWAYS validate asset.json with ValidateAsset() before using
- Asset state stored in assets/.state/[slot].txt
- Frame files MUST be listed in order in asset.json
- NEVER commit PNG frame files to git
- For mascots: give every trigger an explicit `priority` when a state could plausibly
  compete with another (see Mascot Triggers above) — do not rely on declaration order or
  map iteration to break ties.

## Asset Directory Structure
assets/[type]s/[name]/
  asset.json      — manifest
  frame1.png      — for spinners
  banner.png      — for banners
  divider.png     — for dividers
  [key].png       — for icons
